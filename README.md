# Kubernetes the Hard Way – AWS VMs

Terraform code that provisions the 4 Debian 12 machines needed to follow
[kubernetes-the-hard-way](https://github.com/kelseyhightower/kubernetes-the-hard-way).
Only the VMs are automated: everything else is done manually, following the tutorial.

## Infrastructure

| Name    | Role                   | Instance type | vCPU* | RAM   | Disk (gp3) | Private IP |
|---------|------------------------|---------------|-------|-------|------------|------------|
| jumpbox | Administration host    | t3.nano       | 2     | 0.5GB | 10GB       | 10.0.1.10  |
| server  | Kubernetes server      | t3.small      | 2     | 2GB   | 20GB       | 10.0.1.11  |
| node-0  | Kubernetes worker node | t3.small      | 2     | 2GB   | 20GB       | 10.0.1.20  |
| node-1  | Kubernetes worker node | t3.small      | 2     | 2GB   | 20GB       | 10.0.1.21  |

\* AWS has no 1 vCPU burstable size; the smallest instances matching the RAM requirements are used.

Resources created (all in `infra/`):

- **AMI**: latest official Debian 12 (bookworm) amd64 image (looked up, not hardcoded).
- **Network**: dedicated VPC (`10.0.0.0/16`), one public subnet (`10.0.1.0/24`), internet gateway and route table.
- **Security group**: SSH (22) and Kubernetes API (6443) from `ssh_allowed_cidr`; all traffic between the machines; all egress.
- **SSH key**: ED25519 key pair generated by Terraform, private key saved to `infra/k8s-hard-way.pem` (mode 0600, git-ignored).
- **Instances**: source/destination check disabled so the nodes can route pod traffic between each other, as required later in the tutorial.
- Fixed private IPs, so addresses survive stop/start. Public IPs change when an instance is stopped/started or recreated.

State is stored locally (no remote backend).

## Prerequisites

- Terraform >= 1.5
- AWS credentials configured (`aws configure`, or `AWS_PROFILE` / `AWS_ACCESS_KEY_ID` env vars)

## Create the infra

```bash
cd infra
terraform init
terraform apply
```

Optional: restrict SSH/API access to your IP and/or change the region (default `us-east-1`):

```bash
terraform apply -var "ssh_allowed_cidr=$(curl -s ifconfig.me)/32" -var "region=eu-west-1"
```

## Connect

```bash
terraform output machines            # public/private IPs and a ready-to-use ssh command per machine
terraform output -raw ssh_config     # paste in ~/.ssh/config to get `ssh jumpbox`, `ssh server`, ...
terraform output -raw machines_txt   # machine database (IP FQDN HOSTNAME POD_SUBNET) for the tutorial
```

Example: `ssh -i infra/k8s-hard-way.pem admin@<jumpbox public ip>`.
The default user of the Debian AMI is `admin`; use `sudo` to become root as the tutorial requires.

Machines can reach each other through their private IPs (e.g. from the jumpbox, `ssh admin@10.0.1.11`),
but you will need to copy the private key to the jumpbox or use SSH agent forwarding (`ssh -A`).

## Destroy the infra

```bash
cd infra
terraform destroy
```

This removes everything, including the VMs' data. Run `terraform apply` again for a fresh set of machines.
To save money between sessions, destroy rather than leave the instances running.
